## 1. Immediate goal

Allow a user to drop in **one flattened transparent PNG** of a tree, bush or plant (often generated by ChatGPT), auto-detect likely foliage, inspect the selection, manually correct mistakes, and export an **exactly aligned grayscale foliage mask** for use by the Fantasy 2D Godot vegetation shader.

The mask is the core deliverable, **not** a generated replacement tree. The original sprite stays untouched. Seasonal colour previews are useful and should be built later, but are not a prerequisite for the first useful mask editor.

### Existing normal pipeline (do not replace it)

1. ChatGPT generates a lush green tree with a brown trunk and transparent background.
2. **Pixel Art Converter** applies pixel detail, colours and outlines, using its saved master config.
3. **Sprite Batch** performs final physical resize and optional rename.
4. The **final-size PNG** goes to Godot.

### Temporary separate-tool foliage workflow

5. Independently open **Seasonal Sprite Studio** from BEN TOOLBOX's Game Development tools.
6. Load the **final sprite PNG** into the Studio using its own file picker or drag/drop.
7. Auto-detect foliage, view mask overlay, manually refine or protect bark, and save the mask project.
8. Export e.g. **oak_01_foliage_mask.png** to the folder chosen by the user, then manually import the matching sprite and mask into Godot once that runtime integration exists.

**For now, no extra automatic handoff is necessary.** Avoid embedding the mask editor inside Sprite Batch or changing Pixel Art Converter. These tools must remain independently usable. Once the standalone process has been validated by the user, handoffs and batch automation can be designed as later phases.

## 2. Why a mask rather than another recoloured sprite?

Godot already uses green/pink foliage detection in the shared snow/wetness shader includes. Its future seasonal tint can use the same original-image foliage score, with an *optional* author-created mask to override imperfect automatic detection.

- A **white mask pixel** means foliage can be affected by seasonal tint.
- A **black mask pixel** means preserve trunk/bark/roots/non-foliage.
- **Gray** is partially affected (soft selection edges).

One unchanged tree PNG plus an optional mask should let Godot change leaf colours through the year while preserving its wind, snow, wetness and shadow behaviour. The Studio does **not** need to implement Godot's real-time season simulation.

**Real limitation:** A flattened tree PNG has no recoverable semantic layers. Colour/position heuristics produce a first guess only. Green moss, branch highlights, dark leaves and pink blossoms may be missed or misclassified. The user must be able to paint corrections. A mask cannot reconstruct branches hidden behind leaves.

## 5. Mask model and non-destructive rules

- **OriginalSource**: immutable decoded RGBA pixels, preserved throughout editing; never save changes over the original PNG.
- **AutomaticFoliageMask**: grayscale 0..255 confidence result of colour/position classification.
- **ManualAddMask / ManualRemoveMask** (or equivalent sparse manual overrides): survive detector slider changes and detector recomputation.
- **ProtectionMask**: distinct 0..255 painting layer used to protect brown trunk/branches/roots even if detector thinks they are foliage.
- **EffectiveMask**: the combined final mask for Godot, computed from automatic selection plus manual corrections and protection (clamped to 0..255). The exact add/subtract priority must be documented/tested; protection always wins by default.
- Source alpha remains authoritative: **mask must be 0 in fully transparent source regions**. Transparent surroundings remain unaffected; partially transparent anti-aliased edges should transition cleanly.

Do not confuse a *visibility toggle* with clearing/deleting a mask layer. Loading a previously saved project restores original manual mask edits.

## 6. Required automatic foliage detection

V1 supports **green foliage against brown bark** first, a good fit for the user's lush green oak trees. Start with deterministic local ImageSharp classification; no cloud AI or neural model needed.

Candidate signals:
- Source RGB converted to HSV/HSL or a perceptual colour space; chroma/saturation, green hue band, luminance.
- Optional vertical canopy bias/hint, not a hard rule that destroys low foliage.
- Alpha threshold to reject transparent fringe/noise.
- Optional bounded island removal and edge smoothing/morphology.
- Click a pixel to **Pick Similar Colours** using adjustable colour distance and optionally connected-region selection. This is essential for pink blossom or unusually coloured tree leaves.

Adjustable controls:
- Hue/tint selection or selectable detector profile (green default; later other foliage profiles).
- Colour tolerance.
- Minimum saturation.
- Dark-leaf inclusion.
- Minimum source alpha.
- Canopy bias.
- Edge feather/softness.
- Remove tiny islands.
- Grow/Shrink mask.

**Accuracy contract:** Don't label the algorithm AI semantic segmentation. Provide explicit feedback if detection finds no obvious leaves. Never claim colour-only selection will always avoid trunks.

## 7. Manual editing

Required brush modes:
- Add foliage
- Remove foliage
- Protect trunk
- Unprotect
- Pick similar colour (can be a click operation instead of a brush)

Required interactions:
- Brush radius and strength with click-to-type number and slider.
- Drag strokes interpolated across pointer motion, independent of zoom level.
- Zoom-aware cursor and correct mapping between screen position and original pixel coordinates.
- Bounded undo/redo, preferably stroke/region changes rather than full-size bitmap copy per pointer event.
- Separate **Reset Automatic Detection** and **Clear Manual Corrections**, with appropriate confirmation before destructive manual reset.
- Changing detector settings **must not erase painted corrections**. Preserve protection mask across automatic regeneration.

A user should be able to fix one bark section incorrectly marked green, and include an omitted dark-leaf cluster, with immediate visible results.

## 8. Primary export: foliage mask for Godot

Export a lossless standard **8-bit RGB or RGBA PNG**, with:
- **R = G = B = EffectiveMask intensity** (black 0, gray partial, white 255).
- If RGBA, **A = 255 throughout** (including black, non-foliage, and transparent-background pixels); do **not** encode selection only in alpha.
- Zero mask strength outside the source's fully transparent pixels.
- Exact **width/height, crop, position and transparent margins** of the loaded final sprite.
- No trimming, resizing, recentering, recolouring or hidden canvas changes.
- Suggested filename: \`<sprite_base>_foliage_mask.png\`.

Use an output folder picker and filename preview. Before saving, detect conflicts with existing files and do not overwrite by default. Source PNG cannot be overwritten as the mask output. Support cancellation/error handling and safely dispose of temporary buffers.

Godot integration belongs in the Fantasy 2D repo and is **not part of this standalone editor's V1 implementation**. Once hooked up, Godot samples the mask using the same source-UV coordinates as the wind-deformed artwork. Where no authored mask is present, Godot should fall back to its green/pink foliage heuristic. The mask overrides the colour heuristic so it also selects red/pink/dark foliage correctly.

### Important: final pixel dimensions

The Studio's Godot mask should be authored from the **final PNG produced after Pixel Art Converter AND Sprite Batch**. Even when a pixelation operation retains canvas dimensions, changed leaf boundaries can invalidate a pre-pixelation mask. A downstream resize cannot just resize the tree and leave the mask unchanged.

There should be a visible reminder in the Studio: "**For Godot, load the final-sized sprite before generating its foliage mask.**"

## 9. Project save/load (V1 required)

Persist **per-image editing state** in a user-chosen project location using a versioned JSON manifest and lossless PNG masks (or another clearly documented lossless representation). Include:
- Source path/reference, dimensions and optionally SHA-256 identity hash.
- Automatic detector profile/options.
- Manual add/remove corrections and protection mask.
- Current editor selection/toggles where appropriate.
- Later per-season preview settings (non-destructive).

When reopening: validate mask dimensions and source identity, warn on missing/changed source and require explicit relink/confirmation. A different image must not silently inherit another tree's mask.

Separate **per-image projects** from optional **named look presets** that can be stored under user LocalAppData. Never include export overwrite choices in an artistic preset.

## 10. Seasonal preview (after mask V1 works)

The studio remains called **Seasonal Sprite Studio**, not just Mask Tool, because it can later preview how the mask affects actual artwork.

- **Spring:** light/fresh green tint with preserved leaf shading.
- **Summer:** original or mildly lush green colours.
- **Autumn:** green → yellow → orange → red; warmth/progression slider; preserve natural light/dark variation; trunk and root pixels excluded by mask.
- **Winter:** **leaves remain present**. Cold/de-saturated foliage and optional patchy top-surface snow preview; adjustable coverage/intensity/patch size. No leaf removal or invented branches.
- Original vs seasonal preview and effect toggles; always derive from original source + masks, never bake adjustments over the previous preview.

Studio winter snow is a local approximation; **Godot's existing snow renderer remains authoritative** for runtime snow. CPU Studio preview does not promise byte-exact matching to Godot's shaders.

Later optional exports: \`oak_01_spring.png\`, \`oak_01_summer.png\`, \`oak_01_autumn.png\`, \`oak_01_winter.png\` as separate aligned sprites, with explicit export preflight and no source overwrite. These are **not required** for dynamic Godot seasons.

## 12. Performance and quality

- One selected sprite in memory, selected-image-only preview.
- Cache original decode; changing preview strength doesn't reread PNG or redetect foliage.
- Heavy mask evaluation/rendering off the Avalonia UI thread using immutable captured inputs.
- ~100–150ms throttled/single sequential latest-request-wins preview pump with cancellation/generation tokens; never queue unlimited slider work.
- Brush painting updates only dirty regions where practical; bounded history by bytes/brush stroke.
- Zoom/pan/preview controls must not run an idle redraw loop unnecessarily.
- Safe maximum dimensions/pixel memory budget and clear errors for unreadable, malformed, giant images.
- Dispose bitmaps/streams; close/cancel prevents outdated preview publication or leaked files.
- Keep alpha edges and protected bark exact. Original source file hash must never change.
- Test Win10/11, DPI/layout, slider dragging, zoomed painting, overlay alignment and save/export, not just compilation.

## 15. Critical pitfalls

- **Don't assume a flattened PNG magically contains separate leaf/trunk layers.** Auto detection is heuristic; correction is essential.
- **Don't globally hue-shift brown trunks**; use effective foliage mask, preserve alpha and unaffected RGBA.
- **Don't save source pixels into a mask export**; it must be grayscale RGB with opaque alpha.
- **Don't regenerate and wipe user brush corrections** when a hue/tolerance slider changes.
- **Don't write the mask against a different-size pre-Batch source** and claim it aligns with final Godot texture.
- **Don't add per-tree Godot processors or modify Godot source** as part of an Avalonia Studio coding job.
- **Don't make the standalone Studio wait for the full Godot calendar/shader implementation** before it can be tested.
- **Don't force repeated export/import between BEN TOOLBOX tools yet**. The user explicitly wants manual standalone validation before automation.
- **Don't claim the Avalonia snow preview exactly matches GPU runtime snow**.
